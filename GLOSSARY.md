# evalgate

A regression gate for LLM-powered features: it scores a feature against a human-labeled dataset whenever its prompt or model changes, and blocks the change if quality drops.

## Language

### What gets evaluated

**Feature under test**:
An LLM-powered capability that evalgate evaluates, defined by its prompt, its model and a typed input/output contract.
_Avoid_: App, target, system under test

**Prompt version**:
An immutable, identified revision of a feature's prompt; changing a prompt means creating a new prompt version.
_Avoid_: Prompt file, template

### Ground truth

**Golden dataset**:
The versioned, human-written set of cases that defines what correct behavior looks like for one feature under test. Never generated by an LLM.
_Avoid_: Test set, eval set, fixtures

**Case**:
One entry in the golden dataset: a stable ID, an input, the expected output, a difficulty tag and a note on why it matters.
_Avoid_: Test case, example, sample

### Evaluation

**Run**:
One execution of a feature under test, at a given prompt version and model, over the whole golden dataset, with every case scored.
_Avoid_: Eval, job, execution

**Judge**:
The LLM that rates the free-text part of an output against the expected output. It is always a different model from the one being evaluated.
_Avoid_: Grader, evaluator, critic

**Scorer**:
One dimension on which a case's output is measured, such as an exact match on a field, a judge rating or latency. Each feature under test declares its own scorers.
_Avoid_: Metric, check, evaluator

**Blocking scorer**:
A scorer whose result decides whether a case passes. Scorers that are not blocking, such as latency and token usage, are only reported.
_Avoid_: Required metric, hard check

**Pass**:
A case passes when every blocking scorer passes.
_Avoid_: Success, correct

**Baseline**:
The most recent run on `main`; every other run is compared against it.
_Avoid_: Previous run, reference run, golden run

**Candidate run**:
A run made from a pull request. It is compared against the baseline and never becomes one.
_Avoid_: PR run, test run

**Regression**:
A case that passed in the baseline and fails in the candidate run, and fails again when that case is re-run. A case that fails only once is a flake, not a regression.
_Avoid_: Breakage, failure

**Accepted regression**:
A critical gate verdict that a person deliberately downgraded to a warning on a pull request, with their name on record. Reserved for urgent cases; an intended behavior change should update the golden dataset instead.
_Avoid_: Override, bypass, waiver

**Unbaselined case**:
A case that is new or whose expected output changed since the baseline. It is scored and reported, but kept out of the comparison.
_Avoid_: New case, orphan case

### Verdicts

**Gate verdict**:
The outcome of comparing a candidate run with the baseline: pass, warning or critical. Only critical blocks the merge.
_Avoid_: Status, result

**Drift**:
A gradual quality drop across successive runs on `main`, caught by comparing moving averages rather than single runs. Each step can be too small to trigger a gate verdict on its own.
_Avoid_: Degradation, decay

**Flake**:
A case whose pass/fail result changes with nothing in the feature changed, caused by model non-determinism.
_Avoid_: Noise, flaky test

**Improvement**:
A case that failed in the baseline and passes in the candidate run.
_Avoid_: Fix
